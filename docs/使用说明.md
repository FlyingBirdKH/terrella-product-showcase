# Terrella 工作流与产品册 · 使用说明

> 更新：2026-11-22　｜　适用于当前这套「流程图站 + 产品册仓库 + 本地工作台」组合

---

## 一、三个入口

| 用途 | 地址 | 谁能打开 |
|---|---|---|
| **流程图**（谁负责什么、失败退回哪、哪一步要放行） | https://terrella-workflow.vercel.app/index.html | 任何人 |
| **线上产品册**（对外展示页） | https://terrella-product-showcase.vercel.app/ | 任何人 |
| **本地工作台**（勾选、上传、删图、出图需求、到货核对） | http://127.0.0.1:8788/index.html | **只在运行工作台的那台电脑** |

本地工作台要先启动：桌面双击 **启动 Terrella.cmd**，等约 2 分钟（Docker → 数据库 → 控制台 8790 → 产品册 8788 → 商城 4100）。

## 二、流程图怎么用

### 看
1. 打开流程图站，左侧切三张图：
   - 产品库制作流程（含角色泳道）
   - 三端对账流程（Bunny ↔ 产品册 ↔ 商城）
   - 出图闭环（勾选 → 出图 → 上传 → 核对 → 上架）
2. **搜索框**输入 Canvas ID、文件名、负责人（如 `F0CF`、`Bunny`、`Dot`），命中节点高亮、其余变暗
3. **点任意节点** → 右侧弹出详情：负责人 + 调用的 GitHub / Canvas / Supabase / Bunny 引用
4. 深链可分享：`https://terrella-workflow.vercel.app/index.html#flow=three-way-recon&node=r9`
5. 「导出 SVG」「打印/PDF」可拿去贴文档

### 改（改数据，不画图）
1. 改 `terrella-workflow/workflows.json`（唯一真源）
2. 校验：`node validate-flow.cjs workflows.json`（判断出口、死端、可达、泳道、重叠）
3. 本地看：`$env:PORT=8901; node serve.cjs` → http://127.0.0.1:8901/index.html
4. 提交 + 部署：`git push` 后跑 `vercel deploy --prod`

流程数据规则：一个动作一个节点；判断节点只能有一条「是」和一条「否」；回环用 `dashed: true`；每个节点要有 `owner` 和执行类节点要有 `refs`。

## 三、产品册怎么用

### 看
- 线上：https://terrella-product-showcase.vercel.app/
- 本地预览（含工作台面板）：http://127.0.0.1:8788/index.html

### 改图库数据（已拆成 JSON）
```powershell
cd <showcase 仓库>
node scripts/apply-data.mjs      # 把 data/catalog.json 注回 index.html
node scripts/validate-data.mjs   # 必填字段/尺寸/路径/缩略图/已删图校验
```
- **唯一真源是 `data/catalog.json`**，不要手改 index.html 里那两行 `const GALLERY` / `const AI_GALLERY`
- 改完 `apply-data` → `validate-data` → 提交 PR
- CI 会自动跑 `validate-catalog`，失败就说明数据不合格

### 发布（记住：合并不等于上线）
1. 开 PR → 合并
2. 手动部署：`vercel deploy --prod`（该项目**没有接** Vercel Git 集成）
3. 在正式地址验收，并核对 `https://terrella-product-showcase.vercel.app/version.json` 里的 `sha` 是否等于本次提交

## 四、出图链路怎么走

1. **标需要出图**：本地工作台卡片上点「要出图」→ 会立即把该款需求发到 Slack 线程（DeepseekHarness 身份）
2. **等交付**：出图方出整套（1600×1600、sRGB、画面无文字、左下留白），交付到共享目录并回帖（SKU／版本／张数／尺寸）
3. **上传 + 登记**（出好即传，不等选图）：
```powershell
cd tools\sync-selections
node import-ai-images.mjs --sku CAT-009 --dir "C:\...\出图目录" --version 20261122-v1 --apply
```
   - 会自动：上传 Bunny `products/{系列}/{SKU}/ai/{版本}/` → SHA 读回校验 → 登记 AI_GALLERY → 生成缩略图
4. **到货核对**：面板「到货核对」或 `http://127.0.0.1:8790/api/ai-coverage`
   - 看：张数、尺寸、视角标签、规格不符数量
5. **上架**：页面上勾选放行 → 同步商城 `terrella_skus.images`（写前快照，失败可回滚）

### 两条已定规则
- **样板门**：默认整套一次交齐（2026-11-21 指令）；要「先出 1 张样板」须**下单时写明**
- **历史尺寸**：历史上传的 1254×1024 等非 1600 图**保留并标注「历史旧尺寸（豁免）」**，不重出；**新批次仍必须 1600×1600**

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 面板按钮点了没反应 | 控制台 8790 没启动 | 看顶部红条提示 → 运行启动脚本 → 刷新；或点「重试连接」 |
| 改了图但页面没变 | 没跑 `apply-data` 或没部署 | 跑 `apply-data` → `validate-data` → 部署 |
| 删了的图还显示 | CDN 缓存 30 天，不能用 CDN 判断 | 以 Bunny **源站目录清单**为准（导入脚本已内置） |
| 上传报“规格不符” | 图片不是 1600×1600 | 新批次必须 1600；历史批次会标 legacy 豁免 |
| 面板打不开 / 换电脑打不开 | 服务只绑本机 | 本地工作台只在运行它的那台电脑可用；对外看线上产品册 |
| 线上页面 4xx | 部署包缺文件 | 检查部署目录是否包含 thumbs/、data/、version.json |
